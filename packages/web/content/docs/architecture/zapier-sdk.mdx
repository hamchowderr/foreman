Foreman's 9,000+-app coverage is the Zapier SDK, used directly. We import
`@zapier/zapier-sdk` and auto-generate Mastra tools from its internal
registry — no MCP transport, no child process, no stdio.

## The wire

`packages/agents/src/lib/zapier-sdk-tools.ts` reads the SDK's
`getRegistry()` (the same function list the upstream MCP server uses
internally) and wraps each method with `createTool()`. Method names
convert from `camelCase` to `kebab-case` for tool IDs (`runAction` →
`run-action`).

<Callout>
  This replaced an earlier MCP stdio approach. Cutting out the child
  process means the agent server is deployable to Vercel as well as the
  VPS — there's no persistent stdio pipe to keep open.
</Callout>

## requireApproval

Nine SDK methods write or delete real data. They're listed in the
`APPROVAL_REQUIRED` set in `zapier-sdk-tools.ts`. Each generated tool
checks the set at execution time and surfaces an **action proposal**
instead of running.

The approval-gated tools:

| Tool | Kind |
| --- | --- |
| `run-action` | write |
| `fetch` | write |
| `create-table` | write |
| `delete-table` | write |
| `create-table-records` | write |
| `update-table-records` | write |
| `delete-table-records` | write |
| `create-table-fields` | write |
| `delete-table-fields` | write |

A separate `READ_ONLY` set marks 17 discovery tools (list/get/find) so
they can be exposed to MCP clients with the right annotations.

## Output summarisation

Every tool response passes through a summarizer before reaching the
agent. This compresses verbose API responses:

- Lists cap at 20 items
- Unnecessary fields strip out
- Long strings trim to their most useful prefix

Saves hundreds of tokens per tool call, and makes the agent's context
window go a lot further.

Five thin-wrapper SDK methods (`request`, `listAuthentications`, etc.)
sit in a `DEPRECATED_METHODS` set and are excluded from generation
entirely — the agent only sees the canonical equivalents.

## Modes

Foreman runs in one of two modes:

<Tabs items={["dev", "self_hosted"]}>
  <Tab value="dev">
    Uses your personal Zapier CLI login. One-time
    `npx @zapier/zapier-sdk-cli login` and you're done.
  </Tab>
  <Tab value="self_hosted">
    Multi-tenant. Each user connects their own Zapier account. Requires
    `ZAPIER_CLIENT_ID` and `ZAPIER_CLIENT_SECRET` (from
    `npx zapier-sdk create-client-credentials`). Runs anywhere — your VPS,
    Coolify, Docker host, our hosted environment, etc.
  </Tab>
</Tabs>

Set `FOREMAN_MODE=dev|self_hosted` in `.env`.

## Encryption

In `self_hosted` mode, per-user Zapier OAuth tokens live in the
`zapier_identity` table, encrypted with **AES-256-GCM** using
`ENCRYPTION_KEY` from env. Key rotation rewrites every row.
