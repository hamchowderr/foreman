The editor is a CMS-style system that separates agent configuration from code.
Subject-matter experts, prompt engineers, and product teams can iterate on
Foreman's agents directly while developers keep the codebase stable. The
editor manages two types of resources alongside agents:

- **Prompts** — reusable, versioned instruction templates with template
  variables and display conditions.
- **Tools** — add tools from integration providers, MCP servers, and override
  tool descriptions at runtime.

<InlineTOC items={toc} />

## When to use the editor

- **Let non-developers iterate** — product, ops, and domain experts can tune
  agent behavior without opening a PR.
- **Version everything** — every save is a snapshot; compare, roll back, or
  target any previous version.
- **Run experiments** — A/B test prompts, canary roll out new instructions,
  pin specific users to specific versions.
- **Target specific versions** — pick draft vs. published per request, or pin
  a specific `versionId`.
- **Manage tools at runtime** — add or remove tools, override descriptions,
  swap MCP servers without a deploy.
- **Override code agents** — layer editor instructions and tools on top of
  agents defined in code.

<Callout>
  For building agents entirely in code, see the
  [Architecture](/docs/architecture) section.
</Callout>

## Quickstart

Install `@mastra/editor` alongside Foreman's existing Mastra dependencies.

<Tabs items={["npm", "pnpm", "yarn", "bun"]}>
  <Tab value="npm">
    ```bash
    npm install @mastra/editor
    ```
  </Tab>
  <Tab value="pnpm">
    ```bash
    pnpm add @mastra/editor
    ```
  </Tab>
  <Tab value="yarn">
    ```bash
    yarn add @mastra/editor
    ```
  </Tab>
  <Tab value="bun">
    ```bash
    bun add @mastra/editor
    ```
  </Tab>
</Tabs>

Then wire it into the Mastra instance in `agents/src/mastra/index.ts`:

```typescript
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'

export const mastra = new Mastra({
  agents: { /* foreman, supervisor, discovery, execution, history */ },
  editor: new MastraEditor(),
})
```

<Callout>
  See the [MastraEditor reference](https://mastra.ai/reference/editor/mastra-editor)
  for all configuration options.
</Callout>

## Studio

Go to the **Agents** tab in Mastra Studio and select an agent to edit
(`foreman`, `supervisor`, `discovery`, `execution`, or `history`). Select the
**Editor** tab, modify the system prompt, and save a new draft version.
Publish to activate it for production traffic.

## Programmatic control

Everything Studio does is available over the Client SDK and REST API. Grab
the editor off the Mastra instance and call its namespaces directly.

```typescript
const editor = mastra.getEditor()

await editor.agent.create({
  id: 'support',
  name: 'Support agent',
  instructions: 'You triage customer support tickets for Foreman users.',
  tools: ['search_history', 'run-action'],
})
```

Update an agent's instructions the same way:

```typescript
await editor.agent.update('support', {
  instructions: 'You triage customer support tickets. Escalate billing to a human.',
})
```

The `editor.agent` namespace exposes `getById`, `list`, `listResolved`, and
`delete`. `editor.prompt` mirrors the same shape for reusable prompt blocks.

### Server endpoints

The editor exposes a REST surface on the agent server. The Client SDK wraps
these; version-management endpoints live at `/stored/agents/:id/versions`.

| Method | Endpoint |
| --- | --- |
| GET | `/stored/agents` |
| POST | `/stored/agents` |
| GET | `/stored/agents/:id` |
| PATCH | `/stored/agents/:id` |
| DELETE | `/stored/agents/:id` |

### Automated experimentation

Closed-loop tuning with another agent:

- Run a dataset through the current published agent and score the results.
- Have another agent read failures and propose instruction or tool changes.
- Apply the changes with `editor.agent.update()` (writes to the draft).
- Re-run the experiment on the draft and compare scores to published.
- Promote the draft to published when scores improve.

## What can be overridden

| Field | Description |
| --- | --- |
| Instructions | Replace or extend the system prompt using prompt blocks. |
| Tools | Add from the tool registry, integration providers, or MCP clients. |

`id`, `name`, and `model` come from code and cannot be changed via the editor
for code-defined agents. Variables are read-only.

## Versioning

Every save creates a version snapshot. You get full history, roll back to any
previous version, compare two versions side-by-side, and target a specific
version on a per-request basis.

### Version lifecycle

| Status | Description |
| --- | --- |
| Draft | Latest working copy. Each save creates a new draft. |
| Published | Active version in production. Only one at a time. |
| Archived | Previous version. Restorable. |

### Version targeting & experimentation

- **A/B testing** — split traffic between two versions and compare metrics.
- **Canary rollouts** — route a small percentage of requests to a new version.
- **Per-user targeting** — pin specific users to specific versions.
- **Environment separation** — draft in staging, published in production.

### Version selection

Pick a version when resolving an agent:

```typescript
const draft = mastra.getAgentById('foreman', { status: 'draft' })
const pinned = mastra.getAgentById('foreman', { versionId: 'abc-123' })
```

Or from the REST API:

```bash
curl http://localhost:4111/agents/foreman?status=draft
curl http://localhost:4111/agents/foreman?versionId=abc-123
```

### Sub-agent versioning

Foreman's supervisor delegates to `discovery`, `execution`, and `history`.
You can pin the sub-agent versions that the supervisor hands off to, from
three layers:

1. **Mastra instance config** — defaults for every request.
2. **Per-invocation options** — overrides passed to `generate()` / `stream()`.
3. **Server request body** — overrides passed by the calling client.

Resolution order: per-invocation > request body > Mastra instance defaults >
code-defined agent.

Instance-level defaults look like this:

```typescript
export const mastra = new Mastra({
  agents: { foreman, supervisor, discovery, execution, history },
  editor: new MastraEditor(),
  versions: {
    agents: {
      discovery: { status: 'published' },
      execution: { versionId: 'abc-123' },
    },
  },
})
```
