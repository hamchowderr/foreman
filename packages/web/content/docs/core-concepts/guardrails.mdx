Foreman ships defaults that make it safe to give an agent real power.
Nothing here is a toggle you have to find and enable — it's on from the
first request.

## PII redaction

The output processor scans every model response for sensitive data:

| Type | Example | Replaced with |
| --- | --- | --- |
| Email | `jane@acme.com` | `[EMAIL]` |
| Phone | `(415) 555-0199` | `[PHONE]` |
| SSN | `123-45-6789` | `[SSN]` |
| Credit card | `3782 822463 10005` | `[CARD]` |
| API key | `sk_live_...` | `[API_KEY]` |
| Bearer token | `Bearer eyJ...` | `[TOKEN]` |

<Callout type="warn">
  Redaction happens on **output**, not input. If you paste an API key into
  a chat, the key sits in your own message history — but it never leaves
  the system in an agent reply.
</Callout>

## Rate limits

Per-user sliding window:

<TypeTable
  type={{
    "per minute": { type: "number", default: "30 actions" },
    "per hour": { type: "number", default: "200 actions" },
    "bulk op threshold": { type: "number", default: "5 records" },

Requests beyond the limit get a friendly "slow down" reply rather than a
500.

## Sensitive app blocking

A curated list of app categories is blocked by default — banking, HR,
security. If you ask Foreman to do a Chase transfer or pull a Workday
record, it refuses and tells you how to opt in.

To allow them (self-host only, admin-only on cloud):

```
Settings → Sensitive apps → [Category] → Opt in
```

## Org admin override

Under a Clerk Organization, admins set guardrail defaults for every
member:

- Allow sensitive apps (on/off)
- Require approval for deletes (on/off)
- Per-user rate limit (N/minute)

Members can't override admin-locked settings.

## Token encryption

Zapier OAuth tokens are stored encrypted at rest with **AES-256-GCM**. API
keys for programmatic access (MCP, A2A) are **SHA-256 hashed** — never
stored in plaintext. The encryption key comes from the `ENCRYPTION_KEY`
env var on self-host, or is managed automatically on cloud.
