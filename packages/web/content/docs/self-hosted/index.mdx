title: Self-hosting
description: Run Foreman on your laptop or your own VPS.

Foreman is MIT-licensed. Run it locally or on any VPS — your data never
leaves your box.

<Callout type="info">
  You'll still need your own Zapier account and API keys from Anthropic and
  OpenAI. Foreman never ships with credentials baked in.
</Callout>

<Callout>
  Foreman requires a Postgres instance with the
  [`vector`](https://github.com/pgvector/pgvector) extension enabled —
  [Supabase](https://supabase.com), [Neon](https://neon.tech), or a
  self-hosted `postgres` + `pgvector` both work. Point `DATABASE_URL` at
  it; the initial migration runs `CREATE EXTENSION IF NOT EXISTS vector`
  before creating any vector columns.
</Callout>

## Quickstart

<Steps>
  <Step>
    ### Clone and install

    ```bash
    git clone https://github.com/hamchowderr/foreman.git
    cd foreman
    npm install
    ```
  </Step>

  <Step>
    ### Boot a local Supabase

    Foreman uses Postgres + pgvector and Supabase Auth. The Supabase CLI
    boots both in a single Docker stack on shifted ports (so it doesn't
    collide with anything else you're running).

    ```bash
    npx supabase start
    ```

    This applies every migration in `supabase/migrations/` automatically.
    Postgres listens on `127.0.0.1:54422`, Studio on `127.0.0.1:54423`.
  </Step>

  <Step>
    ### Set environment variables

    Create `packages/agents/.env.local`:

    ```bash
    DATABASE_URL=postgres://postgres:postgres@127.0.0.1:54422/postgres
    ENCRYPTION_KEY=<64-char hex>
    ANTHROPIC_API_KEY=sk-ant-...
    OPENAI_API_KEY=sk-...
    SUPABASE_URL=http://127.0.0.1:54421
    SUPABASE_SERVICE_ROLE_KEY=<from `npx supabase status`>
    FOREMAN_MODE=self_hosted
    ```

    And `packages/web/.env.local`:

    ```bash
    NEXT_PUBLIC_AGENT_SERVER_URL=http://localhost:4111
    NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54421
    NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<from `npx supabase status`>
    ```

    Generate the encryption key:

    ```bash
    node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
    ```
  </Step>

  <Step>
    ### Run

    ```bash
    # Agents server (build first — `mastra dev` is unstable on Windows)
    cd packages/agents && npm run build && npm run start

    # In another terminal: the web frontend
    cd packages/web && npm run dev
    ```

    Open `http://localhost:3000`, sign up with Supabase, and click
    **Connect Zapier**. Same flow as the cloud version.
  </Step>
</Steps>

## Running on a VPS

The agents service ships with `Dockerfile.agents` for container deploys
(Coolify, Fly, plain `docker run`). The web frontend deploys to Vercel,
Cloudflare, or anywhere Next.js runs. Both services need their own
environment variables — see above.

A typical VPS layout:

- Postgres (Supabase, Neon, or self-hosted with the `vector` extension)
- Agents container exposing port `4111` behind a reverse proxy
- Web frontend on Vercel or the same VPS, pointing
  `NEXT_PUBLIC_AGENT_SERVER_URL` at the agents host

Behind HTTPS with Caddy:

```
foreman.yourdomain.com {
  reverse_proxy agents-host:4111
}
```

## What's different vs cloud

<Callout>
  Feature parity is the goal. These differences are mostly about ops.
</Callout>

| | Cloud | Self-host |
| --- | --- | --- |
| **Upgrades** | Automatic | `docker pull && docker restart` |
| **Backups** | Managed | Your own Postgres instance (`pg_dump`, provider snapshots) |
| **Telemetry** | Opt-in | None |
| **Auth** | Supabase (managed) | Supabase (self-hosted or free tier) |
| **Zapier** | Your personal account | Your personal account |
